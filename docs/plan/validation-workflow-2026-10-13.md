# 验证流程优化：频率、范围与证据复用

状态：维护者于 2026-10-13 同意按耗时诊断建议开始优化；本文件规定后续执行频率。
适用于当前 reliability 方案及后续开发会话，不重写历史报告。
产品任务顺序仍由对应 Sprint 决定；本次不实施 S3-B，也不修改并行中的扫描器优化。

## 1. 本轮范围与验收

| 任务 | 内容 | 验收 |
|---|---|---|
| VOPT-01 | 修复 Windows CI marker 覆盖默认过滤条件；登记 slow | 实际 pytest 收集证明普通 CI 排除 slow、Windows 同时排除 linux_only、nightly 仍选择 slow；不降低覆盖率 |
| VOPT-02 | 分层验证并消除互相重复的执行要求 | AGENTS、val、执行总则和启动提示词引用本文件；五项目、完整 gold、安全及发布门不减少 |
| VOPT-03 | 维护可复用的完整 JSON gold 比对入口 | 命令行退出码、完整差异报告、无效输入、元数据豁免和失败路径有独立回归；不自动更新 gold |

VOPT-03 的首版只负责已有 JSON 产物的完整比对，不宣称自动完成 Gate A。
采集命令、checkout 核验、stderr/文本输出、hints、生成文件和扩展场景仍按下文执行。
不在这轮重建大型通用验证平台，不运行真实训练、推理或付费 API。

## 2. 为什么调整

S3-A 两项最终质量门合计约 13.4 分钟；两项 Gate A 合格命令的累计耗时
约 34.2 分钟，合计约 47.6 分钟，尚未包含开发、审阅、CI 和失败重跑。
其中 lm-eval 占 Gate A 命令耗时约 81–83%。命令累计时间不等于会话墙钟时间。
依据为 `docs/dogfooding/2026-10-13-reliability-s3a/` 中
`r07a-quality.json`、`r07b-quality.json` 和对应 Gate A 执行记录。

因此保留五项目与完整断言，减少重复的全量检查和无关组合；扫描器本身的性能修复
单独处理。新增候选案例研究文档不自动成为第六批强制验证门。

## 3. 执行频率（唯一权威定义）

昂贵检查前先核对上一报告的环境前提：锁定依赖、Python/uv/Git 版本，以及生成器
使用的 Git 能力。本机 Git 2.25.1 不支持 quickstart 的 `git init -b`；先验证
受支持的 Git 或已审阅的进程级兼容包装器，并让 quickstart freshness 成功，再启动
全量 pytest。不得默默省略 quickstart 或改测试掩盖环境失败。
已有兼容器依据见 `docs/dogfooding/2026-10-10-reliability-s1a/r00-quality.json`；
使用前核对原始文件及 SHA-256，不从历史文档自动执行未经核验的脚本。

| 时点/改动类别 | 必须执行 | 完成边界 |
|---|---|---|
| 每项产品代码任务 | 先失败后通过的定向回归；受影响文件的 lint/type 检查；涉及安全边界时立即跑相应安全回归 | 可形成任务提交，但不宣称会话已验收 |
| 产品开发会话收尾、推送前 | 一次最终完整质量门；五项目 Gate A 基础层及受影响扩展层 | 最终输入一致且全部适用断言通过；各任务引用同一份收尾证据 |
| 仅文稿/计划/导航 | 链接、内容一致性；受影响的生成文档 freshness | 记为文档检查，不冒充产品质量门/Gate A PASS |
| 仅 CI、测试或验证工具 | 工具本身的正反例回归和一次最终完整质量门；按需使用轻量 fixture 验证工具接线 | 产品 Gate A 记 NOT_APPLICABLE 并解释范围；不声称验证了产品语义 |
| 里程碑/发布 | 完整质量门、完整适用 Gate A/B、发布方案要求的 wheel 和跨平台检查 | 资源缺失记 BLOCKED，不能 release-ready |

有任何产品源码、默认配置、profiles、模板、依赖、schema 或打包行为变化，
不能套用文稿/工具例外。无法确定影响范围时按产品会话处理。
仅改测试也必须最终跑全量，不能只证明新增测试自身通过。

“一次”是同一有界会话的最终输入，不是跨会话永久缓存。测试后修改源码、测试、
依赖、配置、schema、工具或相关 CI 设置，相关证据失效；收尾重新跑完整质量门。
纯报告补充无需重新执行产品命令。失败先用最小复现修复，再跑最终完整门；
不在每次定位失败、补充报告或打任务提交前机械重跑全套。

完整质量门内容仍见 [执行总则 §6](reliability-2026-10-03/00_Execution_Guide.md#6-质量检查每项代码任务与会话)：
pytest 覆盖率 ≥85%、redaction 分支 100%、security、ruff、mypy、schema 及生成文档 freshness。
跨平台 CI 不能由 Linux 本地结果替代；任务验收和专项安全断言不可删减。

## 4. Gate A：基础层 + 受影响扩展层

gold、pins 和资源激活条件仍唯一来自 [val.md](../../val.md)，不在这里复制。
每次产品会话所有五个 checkout 均须核验 SHA、origin 和 tracked/untracked 干净状态。

- 基础层：每项目一次新鲜 L0 JSON audit，保留 stdout/stderr；比对完整报告，
  以及 val 要求的完整 detection/hints、路径/行号与诊断。JSON 没有的字段须另行采集，
  不能因为 summary 相同或脚本返回成功而省略。已有基线完整断言继续有效。
- 扩展层：会话改变的每个非资源命令仍在全部五项目执行；共享扫描/检测改动
  按受影响消费者加入命令。涉及 init、检测、manifest 或 L1 规则时，五项目
  均在一次性副本执行 init → L1。不修改正式 checkout。
- 文本 renderer/verbosity/诊断改变时，加入默认文本、verbose 及受影响格式的断言；
  未改变这些路径时不强制每项目同时重复默认、JSON、verbose、每种格式与四个模板。
- 模板、task selector、交互模式等只添加受影响变体；未触及的组合由单元/fixture
  和里程碑完整矩阵守护。任务卡明确要求的特殊负例、边界和跨消费者断言优先保留。

运行前写下“改动 → 受影响命令/变体 → 独立预期”的简表；遗漏、未知、崩溃或
未解释的差异不通过。自动脚本只是执行/比对工具，不能决定新的 gold。

## 5. 证据复用与报告

允许引用已审阅且不可变的旧版本 oracle 产物，前提是源版本、五项目 pins、输入
文件哈希、命令参数、schema、Python/依赖环境及相关配置均有记录且适配本次比较。
不满足时重新建立旧版本证据；不得直接复制当前输出填充预期。
当前版本的运行证据不跨产品代码变化复用；同一输入失败后的辅助比对器修正可以
重比已有原始输出，但须记录原始输出哈希和修正，不能写作新鲜产品重跑。

每条命令保留一次原始产物，汇总报告引用它及其哈希；避免将同一完整 JSON 在
actual、raw、comparison、summary 多处重复嵌入。完整差异和失败证据仍需保留。
报告包含目标 SHA、命令、退出码、耗时、完整差异、适用/不适用/阻塞原因；
区分命令累计耗时和总墙钟耗时，不相加双重计数。持久化报告先检查隐私。

JSON 比对统一使用 `scripts/compare_gold.py`，用法见该脚本 `--help`。
默认严格比较所有字段；`--audit-metadata` 验证 AuditReport 输入后，仅豁免规格
§22 T-02 的根字段 `generated_at` / `reprollm_version`，其他文档没有隐式豁免。
不忽略任意同名嵌套业务字段、
数组顺序、缺失字段、类型或 schema 变化。stderr/文本及生成文件字节另行比较。
首次采用机器可读 expected 文件时仍需记录独立来源/审阅；脚本不生成 expected。
脚本 stdout 为 JSON，退出码为 0（相等）、1（存在差异）、2（输入无效）。报告
保存两个输入的字节哈希及所有差异位置/类型，不重复嵌入原值；原始输入必须保留。
疑似密钥、机器标识和带路径分隔符的字段名在差异路径中使用哈希代号。

```bash
uv run python scripts/compare_gold.py expected-audit.json actual-audit.json --audit-metadata
```

这是纯读取操作；采集命令的非零退出、缺失场景或错误 checkout 不能被“JSON 相等”抵消。

以上频率替代当前执行方案中“每项任务重复完整门”和无条件格式笛卡尔积的描述，
不替代任务验收语义、spec、安全边界或发布门。AGENTS 和启动提示词只引用本文件。
