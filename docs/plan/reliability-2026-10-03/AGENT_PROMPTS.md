# 开发 Agent 启动与接续提示词

版本：v1.2 · 日期：2026-10-03。

以下提示词使用仓库根相对路径，可直接交给能够访问 ReproLLM 仓库的开发 Agent。先提供明确的 Sprint / Session；未来会话的提交、推送与外部操作遵循当时的授权及 [AGENTS.md](../../../AGENTS.md)。

## 1. 第一次实现：S1-A（R00、R01）

这是本轮方案交付时建议的首个开发提示词，已将文件路径替换为仓库中的实际位置：

```text
阅读 docs/plan/reliability-2026-10-03/00_Execution_Guide.md
和 docs/plan/reliability-2026-10-03/01_Persistence_and_State.md，
以及仓库 AGENTS.md、docs/plan/00_architecture_and_decisions.md、
docs/plan/01_specification.md 和 val.md。

执行 Sprint 1 的 S1-A：R00、R01。
先核对当前 HEAD、工作区状态及问题是否仍可复现，再按任务卡开发。
保留已有工作，先建立失败回归，再实施最小修复。
完成规定的质量检查和全部五项目 Gate A，
提交会话报告，列出实际结果、差异、阻塞项及 S1-B 的接续输入。
```

R00 的执行基线需要覆盖当前任务状态，包括 R02-R / R06-G / R04-B 的新增复现及 R05-S 的规范冲突；文档入库和 v1.2 修订验证报告可以作为来源，但不表示 R00 已完成。R01 按验收矩阵检查旧文件字节保全、失败清理与合法项目名，不在 S1-A 顺带实施 R02 / R02-R / R03。

## 2. 后续工程会话

复制前替换三个占位符，确保任务与所选分册中的会话一致：

v1.2 接续顺序：S1-B 为 R02 → R02-R → R03；S2-A 为 R06-G → R05-A → R06-A；S2-B 为 R06-P → R05-B（须有 R05-S 决定）；S3-A 为 R07-A → R07-B；S3-B 为 R04-A → R04-B；S4-A 为 D01 → D02，S4-B 为 D03。D01 的正式验收依赖安全与输入时点修复；需要延期的任务登记具名会话并保留依赖。

```text
在 ReproLLM 仓库执行 <Sprint / Session>。
当前执行文件：docs/plan/reliability-2026-10-03/<Sprint 文件名>。
上一会话报告：<仓库内报告路径>。

先读 00_Execution_Guide.md、当前 Sprint 文件、上一报告、AGENTS.md、
架构决策、规格及 val.md。以实际 HEAD 和已有工作为起点，
按指定 Session 的任务顺序复核问题并开发，不回退到审查 SHA。

每项代码任务先写独立预期的回归，再实施最小修改，
运行规定的完整质量门并记录任务对应提交。
会话结束执行全部五项目 Gate A；仅在适用的里程碑/发布条件下激活 Gate B。
保留全部有语义顺序的观察，检查持久化隐私和新旧产物兼容性。
区分 lock 拒绝写入与 run 脱敏；所有静态内容读取须留在项目根内。
运行输入按采集阶段解释，不能把 post-run 配置或启动前基线自动当成已消费值。

已有具体授权和决定继续有效；只暂停确实依赖新决定或缺少资源的子任务，
先完成可审阅提案/补丁和证据，并继续其他不受影响的任务。
按照总则模板写报告，记录真实命令、退出码、完整差异、资源状态和下一会话输入。
历史成功、未运行测试及 BLOCKED 项不能写成本次 PASS。
```

## 3. 策略审议任务

先选择一个任务号（R05-S、R08-A、R06-B、R07-C、R04-S 或 R08-B）；R05-S 可在 R00 后提前准备，R04-S 只有 R04-A / R04-B 触发条件成立才需要实施：

```text
依据 docs/plan/reliability-2026-10-03/05_Policy_and_Compatibility.md，
处理 <具体任务号>，并遵循执行总则、AGENTS.md、架构决策、规格和 val.md。
先核对最新维护者决定；已有明确批准的范围直接沿用。

如果尚待决定，先完成当前行为与拟议行为对照、源码/上游依据、
具体改动范围、回归矩阵、兼容性与 gold 影响，以及可直接裁决的提案。
R08-A 复用 Issue #9，不新开重复议题，不将更广的参数策略混入。
R05-S 已有明确规范冲突，先形成 §12.2 的具体修订与决定，再合入 R05-B。
R02-R / R04-B 涉及的脱敏模式和输入时点规范按各自任务卡准备材料。
必要的 redaction、engine 或 schema 改动按 D-41 准备明确审阅材料。
保留未决部分的当前合同；其他已授权且不受影响的工作继续完成。
```

## 4. 提前准备验证输入：A01-A

```text
依据 docs/plan/reliability-2026-10-03/06_Validation_and_Adoption.md，
先执行 A01-A：恢复并核验正式验证需要的轻量输入，建立资源阻塞表。
读取执行总则、val.md 和现有 pending-resource-validation.md。
逐项记录固定 upstream SHA、输入路径、校验和、可获取性和独立预期。
仅有 hash 不能视为原文件已经恢复；新建替代案例使用独立 case ID。
完成所有已授权且可获取的准备工作，明确缺失文件及恢复后的首个动作。
真实资源执行按已有授权和本轮实际提供的资源判断；没有运行的门保持未运行或阻塞。
将可用输入交给 D01，保留 formal / supplementary、历史 / 本轮的区别。
```

## 5. 会话结束应提供什么

使用 [执行总则 §9](00_Execution_Guide.md#9-会话报告与下一位-agent-的交接模板) 的完整模板：任务与提交、定向回归、质量门、五项目 Gate A、适用 Gate B、每项语义变化、具体阻塞及下一会话输入。只将有本次证据的结果标为通过。
