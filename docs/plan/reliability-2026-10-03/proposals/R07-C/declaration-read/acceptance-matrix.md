Base: `aee6488078c3435dcc33b20a68cca8bda0d0ec57`. These tests are external full-file proposals; no formal test/product source is modified, no pytest collection or product execution is performed.

The proposed internal map is `Declarations.declaration_read_issues`, appended with an independent empty default. Reasons are only `unreadable` and `invalid_syntax`. ## Deliberate legacy revisions

Exactly 11 existing case outcomes in seven functions change from WARNING to the new INFO/SKIPPED result because the fixture already contains a known manager body-read/decoder failure. Four R06-B functions account for eight cases: three syntax barriers, one malformed alternative Conda manifest, one same-directory inferred-import case and three unreadable barriers. Three env functions each revise their known failed-manifest branch. Explicit empty `qualified_lock_packages` assertions retain the original association proof; valid decoded wrong structures and existing D-F/D-L precedence remain unchanged. All other 137 pre-existing top-level definitions retain exact AST and full source text.

## Static preparation and remaining work

Four full `.py.txt` candidate files parse as Python and pass Ruff checking/formatting. The complete proposed patch passes `git apply --check` without applying it. `metadata.json` records all draft hashes, cases and original-function inventory. `preparation-attempts.json` retains the bounded assembly/snippet guard, one long literal correction, concurrent root proposal-scope guard, and metadata bytes-literal encoding correction. These are external preparation observations, not product test results.

No current crash is claimed from this read-only work. The existing normal read/caught-decoder branches already return safely. Other decoder exception classes and general malformed structure, requirements line/directive/include grammar and listing completeness remain outside this slice. The existing specification explicitly leaves dependency-manifest/requirements uncertainty outside D-F/D-S; D-M therefore needs its own concrete normative acceptance before these formal test/source patches are applied. Formal RED/GREEN and session gates remain NOT_RUN.
