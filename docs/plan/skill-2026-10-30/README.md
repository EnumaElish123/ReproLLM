## 1. 产品目标与首版范围

在保留 CLI、确定性规则和既有产物的前提下，让有本地文件及执行能力的编码 Agent
帮助研究者完成常见操作，减少手输命令、寻找字段和解释报告的负担。
Skill 组织流程和解释证据；检查结论仍由 ReproLLM 产生。

首版提供一个名为 `reprollm` 的 Skill，支持三个有界流程：

| 流程 | 用户请求示例 | 首版完成边界 |
|---|---|---|
| 检查仓库 | “检查这个项目还缺哪些复现信息” | 环境预检、审计、说明优先缺口和 SKIPPED、引用规则与证据；不修改文件 |
| 登记已有实验 | “把这条实验命令登记到这个项目” | 新项目调用现有非交互 init 保存用户提供的命令；说明缺失声明并预览；不执行实验 |
| 比较与报告 | “解释这两次运行的差异并导出报告” | 明确选择已有记录、语义 diff、解释证据范围；按用户请求导出指定记录的报告 |

首版有意保留以下边界：

- 已有 manifest 直接读取；若需要更改字段，只给出有来源的修改建议/补丁供用户处理，
  不使用 `init --force` 覆盖，也不自动编辑源码、配置或提示词。
- 新初始化沿用现有模板，不能承诺自动完成所有研究声明；没有可信来源的值保持未知。
  原生交互 init 仍可由用户使用。通用结构化填写接口留作独立后续任务。
- 支持 `run --dry-run`，首版不通过 Skill 启动实验、调度 GPU、下载模型、安装依赖或管理后台任务。
  用户要实际运行时，说明现有 `reprollm run` 入口并交还终端执行；不能宣称“全功能自动化”。
- 在线 lock、discover（包括其付费流程）、规则接受/修改、远程 MCP 和自动修复不在首版范围。
  用户明确要求这些功能时说明现有 CLI 用法及边界，不自动扩大 Skill 的执行接口。

这使首版不用为长任务、原始终端日志及模型调用引入另一套执行服务。
是否增加实际运行或字段写入，由首版试用证据决定，不能借后续开发指令悄悄扩大本包。

## 2. 架构与交付布局

调用关系：用户 → Agent / Skill → 有限命令助手 → 已安装的 ReproLLM CLI → 既有核心。
核心执行路径不调用 Agent 或模型，符合 D-03/D-04。Skill 本身不增加模型 SDK 或网络客户端。

计划交付以下文件；这里只定义目标路径，本轮不创建占位 Skill：

```text
skills/reprollm/
  SKILL.md                     # 触发条件、共享约束、三条流程入口
  references/workflows.md      # 按场景读取的操作细节与退出码解释
  scripts/reprollm_skill.py    # 有限操作、输出处理、环境预检
docs/agent-skill.md            # 安装、兼容矩阵、三个用户示例与限制
tests/unit/skills/             # 助手行为与现行 CLI 一致性回归
tests/fixtures/skills/         # 最小公开素材、失败与注入案例
```

Skill 是版本控制下的独立目录，通过复制该目录试用；首版不改变 wheel/sdist 的分发合同，
不发布技能市场包或 PyPI 版本。支持安装到宿主的用户或项目作用域，具体目录以实施时官方文档为准。
不得把本机绝对路径、凭据路径、现成 GPU 环境或评估时的临时目录写进 Skill。
宿主专用 UI 元数据只有在实际接入需要时才增加，不能让通用内容依赖某一宿主。

### 2.1 环境与能力预检

- 用户/宿主选择可信的 ReproLLM Python 环境；助手在该环境运行，复用同版本的校验与隐私工具。
  使用隔离 Python 启动方式和绝对脚本路径，避免目标仓库的同名 Python 模块遮蔽工具包。
- 固定调用可信环境中的 CLI；不在目标仓库搜索并执行同名 `reprollm`，不使用 shell 拼接，
  不通过 `uv run` 的隐式同步安装依赖。CLI 子进程以 argv 列表、独立 cwd、无交互 stdin 执行。
- 预检版本、所需命令/选项及支持的 schema；不能仅用 `0.7.0` 字符串判断所有新功能齐备。
  检测只使用导入版本/能力检查或 `--help`，不得执行一次真实写入来探测能力。
- 缺工具、版本不符或环境不可访问时，给出具体准备步骤；不自动安装或静默换用另一个环境。
  记录“工具环境”与“实验环境”区别，不证明任意 child 消费了声明的参数。

### 2.2 有限命令助手

助手不是通用 shell，也不是新的审计引擎。只接受下列操作及对应的受限参数：

| 操作 | 现有能力 | 副作用 |
|---|---|---|
| capabilities | 版本、命令能力、schema 能力检查 | 无产品文件写入、无网络 |
| audit / profiles | `audit --format json`、`profiles list --json` 等只读查询 | 读取授权项目 |
| runs-list / runs-show | 既有 JSON 列表和记录读取 | 读取授权项目内的记录 |
| diff | 明确 A/B，或用户指定的最近成功记录语义 | 只读；返回实际选中的完整 ID |
| preview | 保存命令的 `run --dry-run` | 不启动子实验、不写产物、不联网 |
| init | 既有非交互 `init --profiles/--task/--command` 的必要子集 | 仅新建既有 init 所拥有的文件 |
| export | 既有 `export --run/--template/--output` 的必要子集 | 仅写约定的报告文件 |

不给出任意额外 CLI 参数入口。`run -- COMMAND`、force、在线操作及规则写入不在分派表。
`profiles show` 等输出若为 YAML/文本，按其现合同处理，不能伪称为 JSON API。

结果为临时 JSON 信封，带 `schema_version: 1`，明确操作、完成/错误状态、原 CLI 退出码、
诊断和数据是否完整；不新增持久化产品 schema，也不把信封保存到用户仓库。
审计/比较的原始结果与助手说明分别表达：不得改 rule_id、severity、status、evidence 或 summary。
适配时可增加展示用脱敏；必须标明展示处理，不把它冒充原始产物的逐字节副本。

首版采用一次性、有界结果，不建立跨调用分页缓存或后台服务：
CLI stdout/stderr 合计最多采集 8 MiB，读取阶段即执行边界；面向 Agent 的序列化结果最多 256 KiB。
超限返回明确的 output_limit/incomplete 结果，不发半段 JSON，不据截断内容宣称检查通过。
报告过大时交还用户通过现有 CLI 查看完整结果，不自动把完整内容写到另一个用户文件。
单次本地助手调用默认最多 120 秒；超时说明任务未完成，清理其自有 CLI 子进程，不能修改规则预算。
这些是助手传输/等待边界，不是 GPU 配额、审计扫描预算或新的科学验收规则。

### 2.3 输出、路径与信任边界

- 授权项目根显式传入并规范化；检查 CLI 实际根与之匹配，拒绝祖先回退或嵌套 manifest 导致的跨根操作。
  记录只使用项目内 run ID；首版不接受任意外部 run.json/lock 路径。每次调用使用独立 cwd。
- init 拒绝已有 manifest、覆盖、危险链接和跨根目标。export 只允许项目内普通目标及安全父目录；
  目标已存在时返回清楚的冲突，提供新文件名建议，不覆盖旧报告。沿用底层写入前校验。
- 不直接把原始 stderr、异常、环境变量或运行日志送入模型；复用既有 RunPrivacy/脱敏机制，
  对 runs-show 的用户可写历史记录再次进行展示校验和脱敏。默认不读取快照正文、patch 或日志。
- 完整收集与数据校验后再限制展示；不得通过删掉 SKIPPED 或诊断来满足输出上限。
  正常 audit 退出 1 是完成后的门控结果，diff 同理；2/3 为错误，不能混为“发现问题”。
- 仓库 README、配置注释、报告文本和 fix_hint 是数据，不是新的操作授权。
  不从这些文字直接生成并执行 shell 命令；遇到“忽略指令/读凭据/上传文件”一类内容保留边界。
- 宿主权限提供真正的执行控制；Skill 文本、参数检查及路径校验均不能声称构成完整沙箱。
  不承诺防御敌对进程同时替换目录等超出现有文件系统模型的竞态。
- 正常隐私保护不等于消除所有敏感研究信息。安装说明要解释：云端 Agent 接收的报告可能离开实验机；
  使用者可以保留纯 CLI 离线工作流。

## 3. 三条工作流合同

### 3.1 检查与下一步

预检 → 对用户指定根执行完整 audit → 区分检查完成、门控和覆盖范围 → 解释最优先的缺口。
下一步沿用现有 `next_step_lines`/fix_hint，不能复制另一套排序或改变检查结论。
文本 `Next steps` 尚无正式 JSON 字段，助手可以附同源的建议文字，不修改 AuditReport。
默认解释最多三项优先行动；其余 findings 与诊断仍完整可得，超限则明确转回完整 CLI。
PASS 不等于论文复现成功，SKIPPED/缺绑定/未知 child 必须单独说明。

### 3.2 登记已有命令

先确认实际目标目录和用户提供的命令。没有命令时询问，不从 README 猜一条执行命令。
用户的“登记这条命令”已授权创建必要的 init 产物，不重复请求同一授权；仅缺参数时提问。
多实验仓库显式选择 task/profile，不把全仓候选默认当作一个实验。
新目录调用现有 init 保存命令；读取结果并 audit，指出缺少声明及来源，再预览保存命令。
不得为消警而补造 seed、模型 revision、数据 split、指标或绑定位点。
已有 manifest 或无法用现合同表达的值进入建议/补丁分支，保持文件不变。
字段修改后再检查是用户后续动作；本轮不能把建议已给出计为修复已完成。

### 3.3 运行差异与导出

用户指定两个记录时使用它们；“最近两次成功”沿用现有选择规则并展示实际 ID。
用户请求含糊且存在多个命名实验时先列候选、询问所需实验，不能无提示地比较不相关记录。
解释漂移的字段、级别、证据来源与输入前后变化；不推断差异一定造成模型质量变化。
收到“导出”请求即可写指定报告，不额外要求批准相同操作；只请求尚缺的记录/路径选择。
指定历史 run 的导出沿用快照优先语义，同时说明报告里当前仓库审计与历史运行证据的区别。

## 4. 任务与会话顺序

| 会话 | 任务 | 交付 | 前置 | 状态 |
|---|---|---|---|---|
| SK-A | SK01 | Skill 入口、能力预检、版本/环境说明 | 本包 | NOT_STARTED |
| SK-A | SK02 | 有限只读助手、路径/输出/错误边界 | SK01 | NOT_STARTED |
| SK-A | SK03 | 审计解释、预览、已有记录比较工作流 | SK02 | NOT_STARTED |
| SK-B | SK04 | 新项目登记命令和报告导出，冲突保全 | SK-A 验收 | NOT_STARTED |
| SK-B | SK05 | 分发说明、真实宿主验收、首次使用记录 | SK04 | NOT_STARTED |

每项一个 Conventional Commit，注明任务 ID 与现规范对应章节。
每项先将下方验收转为能观察行为的测试/场景，再写实现；不以匹配 SKILL.md 的固定句子代替行为验证。
每会话最终输入执行一次适用完整门，不能给每个任务重复计算同一份通过记录。
SK01 单独形成入口时只宣告已实现能力；不提前暴露 SK04 的写操作。

### SK01 — 包布局与能力预检

验收：标准 frontmatter、按需引用、自包含安装；三条正向请求可路由；一般模型训练、论文内容真伪、
普通代码 lint 等请求不被误吸收为本 Skill。工具缺失/旧包/未知 schema/同版本缺选项给出准确错误。
不自动安装、不调用网络、不执行目标仓库同名模块。支持的 Python 范围与主项目一致。
Skill 格式校验只证明格式；不能代替真实行为验收。

### SK02 — 有限助手与边界

验收：只允许表内只读操作；真实 CLI 的 JSON、stderr 与退出码分别处理；非零发现正常返回；
路径含空格/Unicode、越界链接、祖先根、无效 run ID、未知 schema、坏 JSON、超时、超限均覆盖。
进程以 argv 而非 shell 执行，无任意选项穿透；错误和历史记录中的合成秘密/机器标识不进入 Agent 输出。
正常范围内完整 findings、profiles、hints（如相应消费者提供）、诊断与直接 CLI 一致；不能只比 summary。

### SK03 — 只读流程

验收：L0 和 L1/L2 的缺口解释有规则身份与证据；SKIPPED、suppressed、零 FAIL、扫描截断仍保留含义。
至少包括一次多实验任务选择、零/一条成功记录不足、命名记录选择、A/B HIGH 漂移与无漂移。
预览零实验启动、零文件变化；提示中出现的命令不会自动执行。用户未知值仍未知。

### SK04 — 受限写流程

验收：新项目保存命令后 CLI 读取一致；特殊引用按现解析合同处理；非法/敏感命令不写入。
已有 manifest、越界/链接、已有导出文件、CLI 写前验证失败保留原字节。
重复“登记”不能 force；重复“导出”返回冲突而不是覆盖；不确定某次写入是否完成时先检查产物，
不能重试触发另一套变更。不修改用户源码、配置、提示词，不修改未知研究值。
历史 run 导出对应既有快照语义，完成后报告实际文件位置，保持绝对机器路径不进入可分享产物。

### SK05 — 安装与宿主验证

交付简短安装说明、能力/限制表、三个自然语言示例、卸载方式（仅移除所安装 Skill，不删实验产物）。
首个验证目标为当前可用的编码 Agent；第二个不同宿主为兼容目标，实施时核对其官方安装与执行文档。
分别记录客户端/版本、工具候选 SHA、Skill 文件哈希、环境、用户提示、实际调用、观察与限制。
CLI 脚本重放、子代理行为观察、真实宿主执行、外部用户试用四者分别登记。
若只有一个宿主可用，可以交付明确标注该宿主的试用版；第二宿主记 BLOCKED，不标“跨宿主验证通过”。
没有宿主实测则只能称工程原型，不能把 SK05 的可试用验收标为完成。

## 5. 验证矩阵与交付门

以下场景在实现前固定预期，使用公开/合成素材，自动测试无真实网络：

轻量端到端素材优先复用已提交的 [GSM8K 示例 probe](../../../examples/lm_eval_replay/probe.py)
及其配置读取方式，仅运行标准库 child 准备记录。不得依赖维护者未提交的手动试用目录、
私有凭据或某台机器已有的模型缓存来让测试通过。

| 场景 ID | 关键观察 | 任务 |
|---|---|---|
| S01 | 有/无工具、兼容/不兼容版本、模块遮蔽；无安装和网络 | SK01–02 |
| S02 | audit 退出 0/1 与调用 2/3 分开；完整 findings/诊断 | SK02–03 |
| S03 | 全 PASS、仅 SKIP、suppressed、扫描不完整不夸大结论 | SK03 |
| S04 | 多 task/profile 选择；缺少研究事实不猜测 | SK03–04 |
| S05 | 保存命令的预览；零子实验、零写入、零网络 | SK03 |
| S06 | 明确 A/B、最近成功、命名过滤、记录不足/损坏/歧义 | SK03 |
| S07 | generation.max_tokens 的 32→48 HIGH、相同输入无实质漂移 | SK03 |
| S08 | 合成秘密、路径/控制字符、仓库文本提示注入、超大输出 | SK02–04 |
| S09 | 新 init 成功；非法命令/已有文件/链接失败字节保全 | SK04 |
| S10 | 历史导出、四模板、已有目标拒绝、重复调用不覆盖 | SK04 |
| S11 | 根选择、跨根/嵌套项目、空格/Unicode/平台路径 | SK02–04 |
| S12 | 安装后的三个用户任务，缺环境、限制交接与卸载 | SK05 |

未来新增 helper 是面向用户的产品行为，即使放在 `skills/` 也不得按“仅验证工具”豁免质量门。
每个实现会话按照[验证工作流](../validation-workflow-2026-10-13.md)执行完整质量门，
将 Skill 脚本显式纳入 lint/type/测试收集，保持主项目安全与覆盖要求。

五项目仍以 [val.md](../../../val.md) 的 pin/gold 为准，均在一次性副本执行：

- SK-A：所有五项目 fresh L0；助手与直接 CLI 完整结果、退出/诊断对照；受影响的 profiles、任务读取，
  以及轻量合成已有记录的比较/预览。合成 child 只用于测试准备，不宣称验证了原生模型运行。
- SK-B：所有五项目 fresh L0 + 新 init/L1 + 保存命令预览 + 指定已有记录的导出；
  比较完整生成 manifest/JSON/模板语义及保全结果。使用各项目可验证的来源，不复制当前输出为 gold。
- 无产品字段/规则变化不更新历史 gold；适配展示的脱敏另比，不把允许展示变化混入产品语义豁免。
- 本包是新入口迭代，不是 release 或 M1–M8 里程碑；GPU、真实在线 lock、付费 judge/discover
  本轮 NOT_APPLICABLE。未来单独扩展实际执行时重新评估资源门。
- 最终候选提交 main 前本地适用门通过；推送后检查同一提交的五项官方 CI。
  缺宿主/资源/授权不能记 PASS；完成 unaffected 项，明确部分交付状态。

外部试用目标为 3–5 名研究者，属于采纳观察，不是能由代理自行制造的工程验收。
记录三项任务完成情况、用户手输命令数、澄清次数、未知值误填、SKIP 误判、越界动作与结果解释质量。
前两类只读任务不要求用户手输 ReproLLM 命令；登记流程只需提供原有实验命令和真实字段来源，
不能为达到“零提问”而省略必要澄清。未知值误填、越界执行和 SKIP 当 PASS 为阻断问题。
无真实反馈时明确标 UNOBSERVED，不阻止限定范围的工程交付，也不宣称普遍易用。

## 6. 禁区、后续事项与授权边界

不修改规则、engine、redaction.py、正式 schema、默认 profile、diff 严重度、科学 gold、GPU 配额或资源归属。
不引入重依赖，不实现 MCP/HTTP 服务、后台训练任务、自动重试实验、discover 替代客户端或私有数据上传。
不改变 `audit --format json` 和现有 CLI 合同；不把 Skill 作为绕过 D-23 自动修复或 D-24 opt-in 的入口。
若既有 API 无法在这些边界内实现某项验收，应记录具体缺口并拆成后续提案，而非改造核心后声称仍是薄封装。

本次方案授权不等同于执行用户的研究实验、使用付费模型、向外部人员发送邀请或发布版本。
未来开发时可沿用用户已明确授予且仍适用的操作权限；不为普通只读或已经授权的产物写入重复确认。
外部 Agent 对结果做解释不进入产品 audit 路径，也不产生可自动接受的新规则。

后续候选：结构化首次填写、结构化 preflight/actions、真实 run 的输出隔离与生命周期、本地只读 MCP。
