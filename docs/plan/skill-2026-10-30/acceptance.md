# Skill v2 验收矩阵

本文件与 [v2 开发方案](README.md)配套。实际执行状态见 [SK2-A](../../dogfooding/2026-10-30-skill-sk2a/README.md)、[SK2-B](../../dogfooding/2026-10-30-skill-sk2b/README.md)及 [SK2-C 报告](../../dogfooding/2026-10-31-skill-sk2c/README.md)；
未记录的后续场景仍为 NOT_RUN，不能把计划表当执行收据。
本轮维护者暂缓 Claude Code 适配；SK20 先验收 Codex，Claude Code 与双宿主门单列为
`DEFERRED_BY_MAINTAINER`，不以登录缺失阻塞其余开发，也不计双宿主 PASS。
按[验证工作流](../validation-workflow-2026-10-13.md)执行，五项目 pin/gold、原生资源配方和
预算条件取自 [val.md](../../../val.md)，不在这里复制或改写历史 gold。

## 1. 测试先行与判定层次

每任务先冻结具体输入和独立预期，再写测试/实现。脚本测试用假传输、假进程和公开合成秘密，
无真实网络；安装、模型、实际宿主与付费验证单列。不得依赖维护者未提交的手动试用材料。
可复用已提交的 [probe](../../../examples/lm_eval_replay/probe.py)构造标准库子程序，
但这种程序不等于模型评测。

每次记录 CLI 候选 commit/wheel hash、Skill commit/文件 hash、命令及参数、宿主/平台、退出码、
耗时、完整结果/诊断及原产物 hash。机密输入只保留存在性或不可逆指纹，不把原值复制到测试报告。
fixture 预期来自规范与源码证据；不能通过复制新输出更新 gold。比较优先级为：

1. 产品语义：完整 findings/profiles/hints/诊断、manifest/lock/run/diff/export/规则状态；
   不是只比 summary，metadata 豁免只能用现验证规则。
2. 适配语义：来源、门控、child exit、完整性、分页范围、展示脱敏和副作用。
3. Agent 行为：选对任务，未知事实不猜测，已有授权不重复询问，未授权操作不执行。
4. 用户体验：从没有 ReproLLM 的环境完成任务，记录用户手输命令和必要澄清，不用作者脚本冒充用户试用。

| A20 | 付费请求超时/响应未知、预算撤销、恢复同一操作 | 不增加外层重试；未知费用保守保留；不伪造候选/成功；没有同意不 accept | SK17 |

所有任务的正向结果、失败保全和隐私边界都必须通过；不存在以“总体通过率”掩盖越界执行或秘密泄漏的规则。
Agent 行为观察需保留提示与实际动作；同一案例重放成功不能删除第一次失败记录。

## 3. 六批阶段出口

| 批次 | 必须新增的证据 | 批次完成后可宣称 |
|---|---|---|
| SK2-A | A01–A05、全新隔离环境安装实测、版本来源和离线探针、五项目 fresh L0 | 自动工具准备可用；不宣称完整工作流 |
| SK2-B | A06–A10/A15、五项目只读结果和诊断完整对照 | 能介绍、检查、预览和比较已有记录 |
| SK2-C | A11–A14/A16、五项目 init/L1/离线lock/规则/四模板及历史导出 | 配置与本地产物流程可用 |
| SK2-D | A17–A20、真实 metadata 和新预算下 discover 全链路 | 已验证的联网/发现功能可用；缺资源分支仍 BLOCKED |
| SK2-E | A21–A23、标准库/安装环境对照、真实 native GPU 与 judge 的适用运行矩阵 | 已验证平台的实际运行、查询和取消可用 |
| SK2-F | A01–A24 汇总、最终安装产物、全命令选项覆盖、真实宿主和完整资源矩阵 | 全部适用门通过才称完整功能；采纳观察另列 |

每批新增助手均按产品代码计，适用 lint/type/security/coverage/schema/生成文档检查。
Skill 脚本显式纳入测试与质量检查范围；每任务定向先失败后通过，每会话最终输入一次完整质量门。
五项目使用原 pin/gold、一次性副本，核验来源/干净状态；原 checkout 不被初始化或写产物。
受影响命令完整对照直接 CLI，adapter 特有展示处理单独比较，不修改原产品 oracle。
仅在满足验证工作流的输入一致与失效规则时复用证据；早期候选成功不能自动算最终候选通过。
推送后核对同一提交五项官方 CI；不以 Linux 本地结果代替跨平台结果。

## 4. 真实资源与安装矩阵

| 门 | 激活时点 | 具体要求 | 不足时状态 |
|---|---|---|---|
| 安装及候选分发 | SK2-A、最终 SK2-F | wheel与固定源码通道各实测；干净用户域/全新 venv、在线正常源和离线 wheelhouse；身份/hash/入口及功能探针，沿用 D02 安装验证 | 通道 BLOCKED；不能把源 checkout 通过当安装通过 |
| 五项目 Gate A | 每个产品实现会话 | fresh L0 + 受影响 init/L1/lock/rules/run/diff/export 等非资源命令；完整 JSON、路径、hint、诊断、产物比较 | 会话不能标完整验收 |
| 真实 metadata | SK2-D、最终 SK2-F | val.md 当前五份公开模型 manifest 与适用模式；正常解析、缓存/离线和拒绝边界分别记载 | 对应分支 BLOCKED，模拟403不等于真实 gated 权限 |
| 真实 discover | SK2-D、最终 SK2-F | 固定公开输入/当前候选、原客户端、当轮新预算；源码证据、接受、缺失→PASS、重复拒绝和隐私全部验收 | 缺凭据/预算/服务时 BLOCKED，mock 不代替 |
| 实际运行及语义比较 | SK2-E、最终 SK2-F | val.md 的五个原生 GPU A/B、完整输入/环境证据与 diff；适用 Linux 安装隔离检查；标准库仅作较早回归 | 无资源分支 BLOCKED；不称训练/推理通过 |
| 真实 judge 捕获 | SK2-E、最终 SK2-F | 使用当前正式 judge 配方和新批准预算，A 验收后 B，核对 JSONL/Python 快照、日志与参数漂移 | 没有预算不能复用历史授权或跳过标 PASS |
| 宿主与平台 | SK2-F | Linux 为完整首要平台；两个真实编码 Agent 宿主分别安装并执行；macOS/Windows 依 D-31 记录能力与限制 | 单宿主只能交付标注范围试用版；未测平台不能称支持 |

资源使用遵循维护者当前授权及实际可用容量，不重新引入已取消的人为共享 GPU 阈值，不触碰他人任务。
付费预算按具体候选、输入、endpoint/model 和尝试上限准备提案，用户批准后执行；
预算不足可请求扩展，不能通过减少必要验收断言或暗改输入标完成。
本计划无需现在批准 GPU/API 使用，当前只修订文稿；后续实际门到执行前准备具体可审阅材料。

自动单元/CI 测试继续无真实网络；包下载、provider 请求和 GPU 配方必须在单独的集成验收中执行。
真实宿主通过与宿主 UI 批准功能、操作系统隔离及运行恢复分别测量，不能以格式兼容推出权限/生命周期兼容。
长任务恢复和取消在每个宣称支持的平台实测；不支持的平台明确禁用该能力，不隐式降级重跑。

## 5. 全功能交付与用户体验

最终清单至少列出：实际支持的命令/选项、安装通道和候选身份、宿主/平台、真实资源结果、
剩余 BLOCKED/NOT_APPLICABLE/UNOBSERVED 项及依据。FULL_ACCEPTED 要求所有适用工程与资源门通过；
可以提前提交部分任务，但不能把“文档已写/代码已推送/某宿主可用”标成全功能已验收。
正式 PyPI/技能市场发布不属于本包，也不是用虚假“已发布版本”满足安装验收的理由。

验收用户流程：

1. 没有 ReproLLM 时说“检查这个仓库”，Agent 自动准备工具并给出有证据的下一步。
2. 仅问“能做什么”，得到简明功能介绍和示例，没有安装或项目写入。
3. 给定命令、环境和适用授权后说“运行并导出”，Agent 完成登记、预览、执行、查询、导出，
   用户不用手输 ReproLLM 命令；失败如实交代，不再自动执行一次。
4. 说“比较最近两次成功实验”，明确记录选择并解释完整漂移和覆盖限制。
5. 正式 discover 在已接受输入和新预算内完成，候选需具体接受后才写规则。
6. 中断对话后恢复长任务查询，或取消自己的运行，原产物和其他任务保持正确。

外部试用目标 3–5 名研究者；记录任务完成、手输命令、必要澄清、错误恢复及证据解释质量。
未知值误填、SKIP 当 PASS、凭据泄漏、未授权执行和重复计费为阻断问题。
外部反馈 UNOBSERVED 不阻止限定范围工程交付，但不能据作者/子代理重放宣称普遍易用或市场采用。
