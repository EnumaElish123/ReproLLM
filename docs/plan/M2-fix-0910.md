## 0. Purpose and precedence

This corrective sprint closes the confirmed defects found after v0.1.0. It does not reinterpret
the Beta architecture or pull M3–M8 features forward. Frozen decisions in
[`00_architecture_and_decisions.md`](00_architecture_and_decisions.md) remain authoritative for
intent; [`01_specification.md`](01_specification.md) remains authoritative for field names and
exact behavior.

Implement tasks in order. Write every acceptance test before implementation. One task is one
Conventional Commit. A task is complete only after its focused tests, the full quality gate, and
the applicable five-repository checks in `val.md` pass.

## 2. Task plan

### M2F-T01 Normalize persisted audit metadata (P1)

**Problems:** F-01, F-02.

**Root cause**

- `cli/audit.py` passes `path.as_posix()` to `run_audit`, preserving an absolute invocation.
- `core/engine.py` serializes that value directly and creates `datetime.now(timezone.utc)` without
  removing microseconds.

**Tests first**

1. Add a CLI test that audits the same materialized repository once through a relative path and
   once through an absolute path. After removing allowed volatile fields, JSON must be identical.
2. Assert `target == "."` when the selected target is the repository root and assert no persisted
   string starts with the temporary checkout prefix.
3. Add a unit test for auditing a repository subdirectory if supported by root discovery; target
   must be a normalized POSIX path relative to the discovered root.
4. Assert `generated_at.microsecond == 0` and JSON uses the `Z` suffix.

**Implementation**

- Resolve the requested path and discovered root, then derive the display target with a small core
  path helper. Use `.` for the root and a repository-relative POSIX path for a descendant.
- Reject any impossible outside-root target with `UserError`; never fall back to an absolute path.
- Generate audit timestamps with `datetime.now(timezone.utc).replace(microsecond=0)`.
- Review fixture snapshots deliberately; only target/timestamp representation may change.

**Acceptance**

- Spec §0 path and timestamp conventions pass for relative, absolute, and symlinked invocation.
- No hostname, username, home directory, drive letter, or `..` is present in persisted JSON.
- All five Gate A reports satisfy `val.md` §3 path requirements.

**Commit:** `fix(audit): normalize persisted target and timestamp (M2F-T01)`.

### M2F-T02 Enforce the CLI error and traceback contract (P1)

**Problem:** F-03.

**Root cause**

The console entry point catches only `UserError` and `ReproLLMError`. Direct `Path.write_text`
failures and other unexpected exceptions escape through Typer/Rich as exit 1 with a traceback.
Global `verbose` is parsed but not made available to the exception boundary.

**Tests first**

1. `audit --format json --output <missing-parent>/report.json` returns exit 2, emits an actionable
   one-line error naming the output path, and emits no traceback.
2. A monkeypatched unexpected exception returns exit 3 with a concise internal-error message.
3. The same unexpected exception under `-v` returns exit 3 and includes a traceback on stderr.
4. Existing `typer.Exit`, audit threshold exit 1, and child-command exit semantics remain unchanged.

**Implementation**

- Introduce a minimal CLI context/state carrying `verbose` and `quiet`; keep it free of domain data.
- Convert user-fixable output `OSError` values at the command boundary into `UserError` with the
  exact path and operation.
- Add a final unexpected-exception branch in `cli()` that emits a traceback only when verbose and
  exits 3. Preserve `KeyboardInterrupt`/Typer exit behavior.
- Do not create missing output parents implicitly unless the specification is changed first.

**Acceptance**

- Every CLI failure is classified as exit 1, 2, 3, or a documented child exit.
- Default output never exposes a traceback; `-v` does for internal failures.
- Tests cover stdout/stderr separation.

**Commit:** `fix(cli): enforce error exit and traceback contract (M2F-T02)`.

### M2F-T03 Qualify `pyproject.toml` dependency manifests (P1)

**Problem:** F-04.

**Root cause**

`scan_dependencies` sets `manifest_present` from filename presence before parsing TOML content,
while spec §12.2 requires `[project]` or `[tool.poetry]`.

**Tests first**

- `[tool.ruff]` only → dependency manifest absent and `env.dependency_manifest_present` CRITICAL.
- `[build-system]` only → absent.
- `[project]` with an empty dependency list → present.
- `[tool.poetry]` with or without dependencies → present.
- Invalid TOML → deterministic unparsed diagnostic and no false PASS.
- A valid requirements/environment/lock/Pipfile still makes the manifest present independently.

**Implementation**

- Make `_parse_pyproject` return structured presence information in addition to declarations, or
  parse once and update `Declarations.manifest_present` only after a qualifying table is found.
- Keep syntax failures in `unparsed`; do not treat an unreadable filename as proof of a manifest.
- Preserve deterministic ordering and avoid a second TOML parse.

**Acceptance**

- Spec §12.2 filename-plus-table semantics are exact.
- Existing fixture results remain unchanged; add a dedicated tool-only-pyproject fixture or unit
  case to prevent regression.

**Commit:** `fix(deps): require project table in pyproject manifests (M2F-T03)`.

### M2F-T04 Report physical dependency declaration lines (P2)

**Problem:** F-05.

**Root cause**

TOML decoding discards source locations. The parser substitutes PEP 621 array indexes and uses zero
for optional dependencies; Poetry entries similarly use mapping iteration indexes.

**Tests first**

Create TOML cases with blank lines, comments, multiline arrays, inline arrays, optional dependency
groups, repeated package names in separate groups, Poetry string constraints, and Poetry inline
tables. Assert each `DependencyDeclaration.line` points to the physical line containing its source
declaration and is always ≥1.

**Implementation**

- Parse values with `tomllib` for correctness.
- Build a deterministic source-location index from the original text, scoped to `[project]`,
  `[project.optional-dependencies]`, and `[tool.poetry.dependencies]`.
- Match each parsed entry to the next compatible physical occurrence; handle repeated entries in
  source order. Keep a fallback diagnostic rather than emitting line 0.
- Do not add a TOML parser dependency solely for locations without a separate maintainer decision.

**Acceptance**

- Every dependency finding points to an existing physical line containing that declaration.
- All five repositories emit no `line: 0`; spot-check the package/path pairs in `val.md` §4.

**Commit:** `fix(deps): preserve physical pyproject evidence lines (M2F-T04)`.

### M2F-T05 Count normalized keyword concepts once (P1)

**Problem:** F-06.

**Root cause**

`keyword_matches` normalizes hyphen/underscore/space, but `_scan_keywords` iterates the original
alias list and increments confidence for each alias that matches the same semantic span.

**Tests first**

- One `Red-Team` span → safety low, not medium.
- One `dp_sgd` span → privacy low.
- One `tool-call`/`tool_call` span → agent low.
- `Red-Team` plus an independent `refusal` signal → safety medium.
- Repeating one concept in multiple files does not simulate two distinct keyword concepts.
- llm-dp-finetune gold regression: safety low and `init` excludes safety.

**Implementation**

- Canonicalize configured keywords with the same separator normalization used by the matcher.
- Group aliases by canonical concept before scanning. Record at most one confidence hit per concept;
  retain a deterministic representative evidence location and spelling.
- Base medium confidence on at least two canonical concepts, not raw alias count or occurrence count.

**Acceptance**

- All keyword-boundary negative tests still pass.
- Five-repository profile output matches `val.md` §5 exactly.
- llm-dp-finetune `init` produces `[finetuning, privacy]`.

**Commit:** `fix(profiles): deduplicate equivalent keyword signals (M2F-T05)`.

### M2F-T06 Implement evaluation directory signals (P1)

**Problem:** F-07.

**Root cause**

The detector gathers directory names but the evaluation table contains only `mmlu`, `gsm8k`,
`benchmark`, and `accuracy`. Spec §13 separately requires exact `eval`/`evaluation` directory names.

**Tests first**

- A directory segment exactly equal to `eval` → evaluation low.
- `evaluation` → evaluation low.
- Both aliases together still represent one directory concept and remain low.
- One directory concept plus `benchmark` → medium.
- `evaluations`, `eval_utils`, and prose substring matches do not gain this special directory signal.

**Implementation**

- Add a typed/exact directory signal rather than a generic README keyword.
- Feed it into the same canonical-concept counting path introduced in M2F-T05.
- Include repository-relative evidence for one representative path or a clear directory note.

**Acceptance**

- Spec §13 directory behavior passes without increasing false positives in the five-repository gold.
- LlamaFactory remains evaluation medium for independently sufficient signals.

**Commit:** `fix(profiles): detect eval directory signal (M2F-T06)`.

### M2F-T07 Surface scan and parse diagnostics under `-v` (P1)

**Problem:** F-08.

**Root cause**

`RepoScanner.warnings` and `PyScanResult.warnings` are populated but discarded when `run_audit`
returns. The global verbose option has no state or output path.

**Tests first**

1. A generated 501-file repository emits one deterministic truncation warning under `-v` and no
   warning by default.
2. A syntax-error target file and an unreadable/oversize file are reported under `-v`.
3. Diagnostics go to stderr, leaving JSON stdout valid.
4. Repeated scanner access does not duplicate a diagnostic.
5. lm-evaluation-harness reports `python file scan truncated to 500 of 816 files`.

**Implementation**

- Add an explicit diagnostics sink/result channel between the engine and CLI; do not add
  undocumented persisted fields to `AuditReport`.
- Merge, deduplicate, and sort scanner and AST warnings after all lazy scans have executed.
- Print diagnostics only when the CLI context from M2F-T02 is verbose. `quiet` suppresses
  non-essential success text but never suppresses errors.

**Acceptance**

- `audit --format json` remains exactly one JSON document on stdout.
- `-v` discloses every incomplete-analysis reason and absolute local paths do not appear.
- The lm-eval boundary in `val.md` §3 is observable.

**Commit:** `fix(audit): expose deterministic scan diagnostics (M2F-T07)`.

### M2F-T09 Restore thin CLI boundaries (P2/refactor)

**Problem:** F-10.

**Root cause**

`cli/init.py` owns detection interpretation, required-field trees, prompt parsing, rendering, and
filesystem transactions. `cli/doctor.py` owns executable/package/network probes. These behaviors are
harder to reuse and test independently from Typer.

**Tests first**

- Characterize current init YAML snapshots, force behavior, interactive values, and error messages.
- Characterize doctor JSON/text results with stubbed process/network adapters.
- Add pure-unit tests for the extracted services before moving command wiring.

**Implementation**

- Move init planning/render data construction into a focused service module; isolate owned-file
  writes behind a small scaffold writer. Keep Typer prompting in the CLI and pass collected values
  to the service.
- Move doctor checks into a core diagnostics service whose subprocess/HTTP collaborators remain
  stub-friendly. CLI selects output format and exit code only.
- Preserve byte-for-byte user-facing output unless another task explicitly changes it.
- Avoid a broad framework or generic service layer; create only the two concrete seams required.

**Acceptance**

- CLI command functions parse arguments, call one service, render/exit, and contain no domain-tree
  construction or system probing.
- Existing snapshots remain stable and full quality gate passes.

**Commit:** `refactor(cli): extract init and doctor services (M2F-T09)`.

### M2F-T10 Make profile detection configuration single-source (P2/refactor)

**Problem:** F-11.

**Root cause**

Built-in profile YAML files define `detect.imports/dependencies/keywords`, but the detector uses
separate `_IMPORT_SIGNALS`, `_DEPENDENCY_SIGNALS`, and `PROFILE_KEYWORDS` tables. Editing a profile
requires synchronized changes and the loaded `ResolvedProfiles.detect` is not the detector input.

**Tests first**

- For every shipped profile, assert loaded YAML signals equal the detector's effective generic
  signal set.
- A temporary user profile/override has a documented deterministic detection result.
- Specialized AST signals (Trainer import, HF IDs, trust_remote_code) and provider/backend hints
  retain their confidence and evidence.
- Report-only rag/agent signals remain available without pretending those profiles ship.

**Implementation**

- Consume built-in/user profile `detect` blocks for generic imports, dependencies, keywords, and
  file/directory signals.
- Keep only semantics that cannot be represented by the profile schema in Python: confidence rules,
  Trainer AST recognition, hints, shipped/report-only metadata, and canonical keyword matching.
- Place rag/agent report-only descriptors in one clearly named internal source until those profiles
  ship; do not duplicate shipped profile lists.
- If user-profile detection semantics are underspecified, open a spec issue and implement only the
  built-in single-source portion.

**Acceptance**

- Changing one shipped profile signal requires editing one authoritative definition.
- Loader, detector, `profiles show`, `init`, and all five gold cases remain consistent.

**Commit:** `refactor(profiles): drive detection from profile definitions (M2F-T10)`.

## 5. Full completion gate

For every task:

```bash
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run mypy src/
uv run reprollm schema export --out /tmp/reprollm-schemas
diff -r schemas /tmp/reprollm-schemas
```

Then execute `val.md` Gate A on all five pinned repositories. The session report must contain:

- task IDs and commit hashes;

- explanations for every intentional baseline change;
- blockers for unavailable resource gates;
- confirmation that generated artifacts contain no absolute paths, usernames, hostnames, or secrets.

The corrective sprint is complete when all unblocked M2F tasks pass, M2F-T11 is either completed or
explicitly recorded as waiting for maintainer sign-off, five-repository Gate A matches the gold, and
CI is green.
