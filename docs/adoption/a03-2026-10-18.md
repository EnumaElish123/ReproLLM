## 维护用途与叙述草稿

以下是内容草稿，段落后的 Claim ID 用于审阅追溯，不是当前官方表单字段。
提交前按真实表单重新组织并检查长度；不对资格或审批结果作保证。

> ReproLLM is an Apache-2.0 CLI for researchers who need to record and compare
> LLM experiments. It captures model, tokenizer, prompt, judge and execution
> state through a manifest, lockfile and runtime records, then reports semantic
> drift and exports a reproducibility report. The audit path uses deterministic
> rules; model-assisted discovery requires explicit opt-in. [F01–F02]

> Our reliability work has addressed input preservation, secret handling,
> dependency interpretation, source scanning and the distinction between
> recorder observations and verified experiment behavior. The engineering work
> is recorded in session reports, including candidate-wheel installation and
> publication gates. The current 0.7.0 development candidate remains unreleased.
> [F03–F04]

> Reviewable evidence includes a bounded native lm-eval A/B case and a shared
> standard-library replay package. The latter ran 44 commands and captured six
> runs across two fresh installations of one verified wheel. It includes
> independent bounded consumption receipts, exact input hashes, complete drift
> explanations and selected-run exports. This is supplementary evidence, not
> completion of all native or resource-dependent acceptance. [F06–F07, F10]

> We validate against five pinned upstream repositories. These are validation
> targets rather than evidence of upstream adoption. The A01 local quality
> record contains 2,800 passing tests with explicit skips and platform limits;
> real independent trial and sustained-adoption evidence remain pending.
> [F08–F09, F11]

> We would use Codex for concrete maintenance work: reproducing issues with
> minimal synthetic cases, writing regressions before bounded fixes, checking
> Python/platform compatibility, keeping recipes and documentation aligned,
> and preparing source-backed policy proposals. Maintainers retain decisions
> about defaults and compatibility. Changes involving redaction, the rule
> engine or schemas require explicit maintainer review under D-41.
> [Maintenance plan: current execution guide and architecture decisions]

> Codex coding-maintenance support is separate from research inference or
> provider API spend. No GPU allocation, paid API budget or gated-model access
> is assumed here. Exact input recovery and the remaining resource gates stay
> visible, and we will not represent this work as release readiness or
> independent adoption. [F05, F11–F13]
