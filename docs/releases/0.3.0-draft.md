## Proposed release notes

ReproLLM 0.3.0 records how an experiment ran, then compares structured runtime
evidence with its manifest and lock. For example, a declared temperature `0.0`
and captured CLI temperature `1.0` produce a CRITICAL finding with both values
and the config/environment observations retained.

This is the **first release of the run record schema v1 writer**
(`.reprollm/runs/<run_id>/run.json`, `schema_version: 1`). Existing manifest and
lock schemas remain compatible. Schema exports have not changed; no migration
from an earlier supported run writer is required.

- `run -- CMD` preserves arguments and child exit codes, writes crash evidence,
  captures bounded hardware/scheduler metadata, and optionally saves redacted logs.
- `runs list` and `runs show` inspect records, with JSON output and unique ID prefixes.
- Audit loads valid records, warns about corrupt ones, and compares the latest
  run's files, generation parameters, model identities, critical package versions
  and accepted custom bindings. All registered rule placeholders are now gone.
- The redaction policy applies nine pattern classes and presence-only credential
  capture. Run persistence removes current machine identity and absolute paths.
  Forbidden inputs are never snapshotted. Original hashes and redacted snapshots
  are intentionally distinct; child-created files remain the child's responsibility.
- CI and release builds have a dedicated leakage gate. The core redaction module
  retains 100% branch coverage. See [runtime capture](../run.md) and
  [private security reporting](../../SECURITY.md).
