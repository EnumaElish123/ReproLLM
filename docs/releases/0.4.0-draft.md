# ReproLLM 0.4.0 — released 2026-09-28

**Released as a consolidated 0.4.0** by maintainer decision: the M4 (lock), M5
(run + redaction) and M6 (diff) work ships together; 0.2.0 and 0.3.0 were never
tagged or published. The prepared-notes sections below are the shipped feature
summary. The former blocker list is replaced by the release-time validation
status, which states plainly what is and is not established.

## Prepared changes

- Compare run IDs/prefixes, run files/directories and lockfiles with `reprollm diff`.
- Use drift table **version 1**, approved by the maintainer on 2026-09-22, with
  profile overrides and package version-component semantics. A torch patch
  update is MEDIUM; a major/minor update is MEDIUM_HIGH.
- Produce JSON and text reports, full summaries, display filters and independent
  `--fail-on` thresholds. Preserve full non-secret hashes in JSON.
- Share the State representation with Level 2 consistency rules while preserving
  existing audit goldens and source evidence. Current audit declarations and
  historical run snapshots retain their distinct roles.
- Add four tested diff scenarios and a [user guide](../diff.md).

The unreleased placeholder diff schema is replaced with the complete v1 shape:
input references, summary, changes and nullable `filtered_below`. Regenerate
consumers of the old placeholder schema. Manifest, lock and run schemas are
unchanged. Comparison occurs before redaction; stored artifacts remain local.

## Validation available

Unit/integration tests cover all four scenarios in JSON and text, schema
freshness, redaction, runtime source conflicts and the existing audit snapshots.
Five pinned repositories pass Gate A and bounded command comparisons. An offline
Project B judge lock pair shows `models.judge.id` HIGH and
`models.judge.pinnability` MEDIUM when moving from a dated snapshot ID to a
floating alias. An installed wheel contains the severity table and produces
valid diff/schema output.

These checks use fixture inputs and small child commands. They do not establish
real inference, judge or training reproducibility. See the
[session report](../dogfooding/m6-second-half.md) for results and limitations.

## Release-time validation status

Completed and verified: the full quality matrix (1254+ tests across Python
3.10–3.12, ruff, mypy --strict, schema freshness, redaction branch gate at
100 %), five-repository Gate A against the pinned gold, fixture-backed lock/
run/diff scenarios, the snapshot-fidelity fix with its end-to-end regression
(`fc3f6aa`), and bounded real-resource supplements recorded in
[`docs/dogfooding/m4-m6-linux-validation.md`](../dogfooding/m4-m6-linux-validation.md):
a real DistilGPT2 DP training pair with capture and semantic drift, a real
lm-eval GSM8K inference pair whose only intended change (output cap 32→48)
surfaced exactly as HIGH drift, and the approved two-attempt DeepSeek judge
supplement under its CNY 3 ceiling.

Published with stated limitations (not silent passes): LlamaFactory training,
local FastChat generation and HarmBench's local target/classifier pairs still
await verified weights and real execution; the original gated Llama-2 DP and
GPT-4 snapshot scenarios remain unreplaced by their supplements; the original
M4 manifest bytes are unrecoverable, so only supplementary metadata manifests
were replayed; and the maintainer's M6-H2 thirty-second readability assessment
of a real paired diff is still open. See `val.md` §§8–9 for the authoritative
gate state and update policy.

The shipped GitHub release notes are the CHANGELOG `[0.4.0]` section. This
document is retained as the release-time status record.
