## Resulting behavior and compatibility

A root loose torch declaration no longer gets credit solely because an
unrelated tools lock contains torch. Format-lock credit requires an actual
same-package declaration from its paired manager manifest, or an import under
the nearest qualified runtime project. The four manager pair definitions,
uncertain manifest barriers, deeper independent roots, component boundaries
and logical aliases follow accepted spec §12.2.

Repository-wide existential exact declarations are unchanged. Nested or
conflicting exact pins still exempt a package. A nested project with its own
actual covered origin can still satisfy the repository-level rule; this does
not prove the root experiment is covered. Lock inventory and presence remain
independent, and exact requirements retain their actual include closure.
Existing evidence/messages, rule IDs, severity, thresholds and persisted
schemas are unchanged. Workspace parent-lock delegation, format/version
expansion, solving, installation and freshness checks are excluded.

`core/deps.py` captures private in-memory project/barrier facts during existing
parsing and exposes one bounded query. `rules/env.py` replaces only the global
format-lock name-credit branch. There is no change to engine, scanner,
redaction, schemas, profiles, dependencies or package version. The accepted
specification patch is applied exactly; its original proposal/patch snapshots
retain their hashes. [Concepts](../../concepts.md#dependency-evidence-in-a-repository)
and CHANGELOG describe the potential new WARNING for unsupported lock inference.
