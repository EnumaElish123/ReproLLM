## 实现

SK10 固定官方源码 `0e0de760fc098634b73bdc64558b5a1086c31232` 的归档 SHA-256、
轻量运行/构建依赖 wheel 哈希、Python/平台范围与产品能力。没有兼容公开发行包时从固定源码构建，
不使用 main/latest，不以相同版本字符串冒充相同来源，也不声称已发布 0.7.0 wheel。

SK11 使用标准库引导和独立用户目录，按当前平台选择 wheel，先验证来源再构建/安装。
安装后核对实际入口、来源、能力与小型离线功能；复用前在可信引导代码中先核验整个环境的文件和权限，
再执行探针。原子激活、并发锁、显式升级/修复、回滚和卸载保留已有环境；带 lease 的环境继续保留。
后续 worker 必须使用 `-I -B` 并管理自己的 lease，避免新字节码被当作安装修改。
SOCKS 使用受限系统 curl，保留原代理；缺少可用通道时给出 HTTPS 代理或已验证离线输入的恢复步骤。
不改动系统 Python、项目/训练环境或全局 PATH；无 sudo、模型下载和研究实验执行。

## 失败、边界与下一批

首次真实安装因完整归档展开约 312 MB 超过原 256 MiB 上限而失败；保留记录后改为安全扫描全归档、
只提取构建输入。最终仅提取 151 文件/779,254 字节。另一尝试因 PATH 中非系统 curl 遮蔽系统 curl 而失败，
补测试后直接查找受信系统路径；最终新目录在线验证通过。没有覆盖或删除失败证据。
独立复核还促成执行前完整性检查、catalog 完整身份绑定、入口权限探针及损坏状态诊断等修复。

真实安装只验证本机 Linux/Python 3.12；跨平台单元 CI 与真实宿主/平台安装分别记载。
本批不是完整 Skill：入口和只读适配从 SK2-B（SK12 → SK13）开始，后续写入、联网发现、实际运行和
跨宿主资源矩阵仍按原计划执行。没有调用模型/provider、使用凭据/GPU/付费 API，也没有发布 release。
使用中环境的 lease 回收与长任务恢复会在 SK19 接线，当前卸载不会猜测其存活状态。
