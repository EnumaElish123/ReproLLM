## 首次失败、修正与复用边界

真实 Git index stat-cache 刷新使只读预览被误判为 staging 改变；`981d2638` 修正观察范围，
七项真实 Git 反例先失败后通过，真实 staging、index flags 和内容变化仍阻止写入。
最终完整质量门和所有五项目门均在修正后重新执行。

原独立 Spec 审阅发现 schema 角色误识别；修正的中间候选又错误依赖 dev-only jsonschema。
最终改为有限标准库识别，并完成独立复验；上述失败均保留，不能计为最终成功。
长操作审阅另发现阻塞 stdin 写与 FIFO 读取：非阻塞 IPC 有五秒期限，交付不明保留 UNKNOWN；
只读取确认的常规状态文件。独立实际受限进程/FIFO 复验通过。

功能矩阵先后保留了 origin 格式差异、验证用小页开销、父控制器停止后的自有空锁、
Git index 刷新，以及 schema 拒绝断言误把 native CLI exit 与 helper OS exit 混为一谈的失败。
最后一项实际拒绝始终是 OS 2、native 0、blocked/needs_authorization，十份旧文件不变；
仅修正验证器并有可审计的延续清单。未把旧失败改写为 PASS。
初始化专项第一轮误用未提供的 `python -m reprollm`，在原生 oracle 失败后停止；
修正为 pyproject 的官方 console entry，在新 fixture 完整重跑，旧轮两次成功不重复计数。

旧特殊专项在 `8573c88b` 的 12 组/48 次实际调用仍为历史观测。
仅复用确认不受 init 修正影响的 7 组：38 个原函数与相关完整 readset 中 160/161 文件未变，
94 份原始流和 16 份产物重新校验；唯一变化为 init 的有限 Git 观察作用域。
这些观测包括已安装长 hash/lease、源与隐私、历史产物及归档冲突边界，不替代本轮新鲜初始化与五项目入口。
父进程中断不会自动清除旧安装锁；本轮仅在证明自有旧任务已退出、无 worker/lease 后移除空锁，
没有修改研究环境或重新安装来掩盖问题。后续恢复指引须保留此限制。

Standards 与 Spec 两轴独立报告：Standards 无硬性问题，原子 I/O 重复为可选 P3；
Spec 的具体问题已修复复验。Git 修正增量两轴无 P1/P2，测试辅助函数重复为可选 P3。
这些审阅不替代资源、真实宿主或跨平台 CI。
