## 先净化，再分享

只提交诊断所需的最少信息，可以完全使用合成项目。不要提交密钥、带认证的 URL、
私有 prompt、数据集记录、模型权重或完整环境变量；不要求上传整个项目或运行目录。

分享前逐项检查命令参数、stdout/stderr、traceback、manifest、lock、run JSON、
JSON/YAML 快照和导出文档。删除或用逻辑标签替换本机绝对路径、用户名、主机名及敏感内容；
自动脱敏不是全面隐私保证。原始材料与原始 hash 留在本机，默认不分享。

用虚构的短输入代替私有内容后，重新确认问题是否仍出现。注明改动了什么；
如果无法安全复现，写明“缺少可分享复现”，不要把修改后的文件称为原始精确输入。
只读检查可在有权检查的既有项目运行；所有 init、lock、run、export 及文件编辑只在一次性副本中进行。
本轮任务不要求执行框架、模型或 API。出现疑似真实密钥泄漏时先停止公开粘贴，
由凭据所有者处理失效/轮换，仅通过获准的私密渠道报告必要信息。

## 问题分类与闭环

| 分类 | 处理口径 |
|---|---|
| bug | 实际行为违反所测版本的合同；保留最小复现和失败断言，关联有边界的修复任务 |
| 文档 | 命令、安装前提、输出解释或版本可用性不清楚；记录具体误导位置 |
| 工作流需求 | 现有合同未覆盖的真实需求；先记录场景与代价，不假定已承诺实现 |
| 超出范围 / 环境阻塞 | 记录所缺版本、输入、权限或资源及恢复动作，不记为通过 |

同一问题可保留多个原因；真实问题才建立 issue/任务。资料不足时标为等待，
不自行补造复现或反馈。可复用[现有 bug 字段](../../../.github/ISSUE_TEMPLATE/bug_report.yml)，
但提交到外部服务和引用试用者内容需相应授权。
